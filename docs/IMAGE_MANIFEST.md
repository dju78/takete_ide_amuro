upload path — every asset is a checked-in file resolved at a stable URL that works identically in dev

## Adding a New Image or Video

1. Drop the file into `public/images/takete-ide/` (or `public/videos/takete-ide/`) with a descriptive,
   kebab-case name.
2. Reference it as `/images/takete-ide/<filename>` (or `/videos/...`) via `next/image` / a `<video>`
   — never an absolute filesystem path.
3. Add a row to the table above.
4. Wrap it in `components/ui/HeritageImage.tsx` rather than a bare `<Image>`, so a failed load falls
   back to a labelled placeholder instead of a broken-media icon.
5. For video, use `components/media/CommunityVideo.tsx` (poster + `preload="none"` + accessible
   title/description) rather than a bare `<video>`, and run
   `node scripts/extract-video-posters.mjs` — with the dev server running — to generate its poster
   frame. `components/ui/HeritageVideo.tsx` remains for the simpler Agado-style embed.
6. If the item belongs to the imported community library, add a record to
   `lib/media/community-media.ts` so it inherits gallery placement, admin editing and the
   verification workflow.

## Quality & Authenticity Notes

Every photograph and every video are genuine community-supplied media — nothing on this list is
AI-generated or stock photography standing in for a specific cultural claim. AI-restyled versions of
several landmark photographs were supplied alongside the originals during the August 2026 import and
were **rejected**; the camera originals were imported instead (see `docs/COMMUNITY_MEDIA_IMPORT.md`). Captions describe only
what is visibly confirmable (e.g. "ceremonial items associated with marriage celebrations") rather
than asserting ritual meaning that hasn't been verified with community sources — see
`docs/HISTORICAL_VERIFICATION.md`. Source photography is modest-resolution community photography, not
studio photography; it is displayed at `object-fit: cover` with content-safe cropping, never stretched
or altered.
